# 练习闭环与问答质量

## 使用

1. 在“我的题库”选择“开始练习”。先展示题干和选项，提交后才展示参考答案、解析及引用。
2. 选择题自动判分。主观题提交后对照答案与原文，选择“自评正确”或“自评错误”，界面明确标注自评。
3. 刷新可恢复记录；未提交草稿保存在当前浏览器。换浏览器可恢复服务端记录，不能恢复尚未提交的本机草稿。
4. 错题可回看引用并“再练一次”。重练冻结原题快照，新增结果，保留旧作答；最新已判分正确后移出待复习错题。题库修改或删除不改变已有快照。
5. “今日复习”优先未完成、待自评、错题，再推荐未练题，默认最多 5 条。最近 7 天统计记录次数，不能当作掌握度或准确率。

问答输入框下展开“资料范围”。默认由问题识别或追问继承范围；勾选“固定使用以下范围”后，明确覆盖继承。场景来自当前课程已完成、有效资料中人工维护的场景键。固定范围选择“不限场景”、清空日期可清除继承限制。范围随会话记录保存，换课程重置控件。

引用展示版本、生效期、权威和择证原因，并打开当前课程的原文件。没有真实页码时不伪造 PDF 定位。历史来源失效、文件缺失或同一文档被重建后会提示核对当前资料；旧快照不冒充现行规定。

## 数据与接口

现有题库 SQLite 文件自动新增 `question_bank_practice` 表，不修改原题库数据。快照独立于题目删除。`request_id` 在课程内唯一，支持网络重试；提交后只能重练，不能覆盖。课程隔离是数据范围约束，不是登录鉴权。

全部练习接口位于 `/api/v1/question-bank`：

| 方法/路径 | 用途 |
| --- | --- |
| POST `/practice` | 指定 course_id、question_id、request_id 开练；重练另传 previous_attempt_id |
| GET `/practice/{id}?course_id=...` | 恢复记录，未提交隐藏答案与证据 |
| POST `/practice/{id}/submit` | 提交选项索引或主观文本 |
| POST `/practice/{id}/assessment` | 仅允许已提交主观题自评 |
| GET `/practice-review?course_id=...` | 建议、错题、历史及事实统计 |

GET `/api/v1/documents/scenarios` 返回当前课程人工场景。问答新增可选 `scope_override`，默认 false 保持原调用；true 表示 scenario/as_of 覆盖继承，包括清空限制。复习参数集中于 `src/config.py` 的 PracticeConfig（7 天、5 条推荐、50 条历史）。回退代码不删除新表；回退数据前备份 SQLite。

## 质量基线与验证

`tests/fixtures/qa_baseline/` 包含三份现有课程样例的固定 Markdown 快照，以及一份明确标注的人工冲突草案。30 条问题覆盖公式、表格、适用范围/时效、权威冲突、跨课和无证据拒答。不覆盖真实 PDF 视觉读图，不是全课程正确率评估。

```powershell
uv run --no-sync python tests/eval/run_qa_eval.py
uv run --no-sync python tests/eval/run_qa_eval.py --live --output docs/artifacts/quality/qa-baseline-after.json
uv run --no-sync pytest -q
```

默认只校验锚点；`--live` 使用当前 Embedding/LLM，向外部模型发送固定样例并在临时库入库。报告保留回答、引用、耗时和机器异常标记，事实正确性需另行复核。

2026-09-30 首次运行完成 30 条，其中 3 条无支持结论却返回 grounded=true；修复生成阶段无证据协议后再次完成 30 条，拒答/来源机器异常标记为 0，四条负例均返回固定拒答且无引用。首份报告的 Windows 临时目录清理错误发生在问答全部完成后，第二轮修复清理路径并正常结束。前后报告为 `docs/artifacts/quality/qa-baseline-report.json`、`docs/artifacts/quality/qa-baseline-after.json`。

本次逐条阅读输出，关键公式、表格数值和正式文件优先的结论符合样例要求。不过引用仍含部分无关召回片段，不能把“0 异常标记”当作引用精准率或全项目准确率。下一轮应扩大真实课程样本，补 PDF 原页/图表锚点，单独评估引用相关性和结论支撑覆盖。

## 第二轮：引用相关性（2026-10-01）

引用保留本次请求的原始 `evidence_index`，筛选后不重新编号，以免正文提及“证据 3”却对应到另一片段；编号是请求内定位，不是全局文档 ID。

生成提示为当前请求的片段赋临时编号，要求模型在隐藏的末尾行标明实际使用的来源。后端只接受本次上下文内的编号，去重后展示选用片段；越界、格式错误、缺失或截断的标记回退为检索候选。SSE 不展示内部来源标记，普通数学不等号仍正常流式输出。

Citation 新增 `evidence_role`：`model_selected` 表示模型标明使用；`retrieval_candidate` 为检索候选，兼容旧模型和历史记录。界面分别显示“模型选用的资料”和“检索候选资料”，提示对照原文核实。模型选源不等于事实验证，旧引用也不被升级为已核实证据。

经用户明确允许向当前 api.xiaomimimo.com 发送固定的 4 份样例，完成同批 30 条评估：引用片段总数从 124 降到 37；26 条可回答样例均保留预期来源，4 条负例仍固定拒答，无机器异常标记。逐条阅读发现个别选源包含正文未实际使用的讨论稿，也存在额外展开内容，因此不宣称引用精准率或结论准确率。

报告：`docs/artifacts/quality/qa-citation-after.json`；对比：`docs/artifacts/quality/qa-citation-after.comparison.json`。本地比较无需再次外传：

```powershell
uv run --no-sync python tests/eval/run_qa_eval.py --output docs/artifacts/quality/qa-citation-after.json --compare docs/artifacts/quality/qa-baseline-after.json
```

新增 `tests/fixtures/qa_pdf/tcp-source.pdf`，原样复制现有课程 PDF。SYN+ACK、ESTABLISHED、端口数字与第 1 页核对一致；原文件中文已显示为圆点，不能作为中文 OCR 或图表质量样本。HTTP 原文件返回与课程隔离通过测试，引用链接带 `#page=1`；当前内置浏览器未渲染 PDF，Edge 连接未成功，多页浏览器跳转尚未验收。该 PDF 仅本地检查，未加入外部评估批次。

## 中文对话检索修复（2026-10-10）

在现有默认课程的 110 个有效切片中复现：进程定义被 BM25 找到，但请求包装词、无关向量和重复导入片段挤占了最终候选。当前 all-MiniLM-L6-v2 将“进程”“电流”编码为未知词，不能用其向量相似度判定这些查询的主题。

检索现在清理请求包装，保留否定、比较、数值和范围；完整候选池先过阈值、去重，再截断。定义问法优先保留直接定义，生成仍使用原问题。查询全部为未知词时只采用当前课程的关键词召回；不静默吞掉模型加载或向量库错误。课程、版本、场景、日期与拒答约束沿用原链路，不修改已有索引或真实模型配置。

同一资料库上 8 条证据锚点对照见 `docs/artifacts/quality/retrieval-chat-repair.json`。这是本地召回检查，包含用户失败问法；不等于全课程准确率，也没有调用远程 LLM。实验表存在电流数值，不能据此编造资料未提供的电流定义。完整离线回归：425 passed、1 skipped、22 integration deselected。
