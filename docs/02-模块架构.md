# 02 模块架构

> RAG 复习助手 · 分层、流水线、数据模型、API  
> 与当前仓库对齐（2026-08）

## 2.1 分层与职责

```
浏览器 UI     frontend/ Vue 3（/sz/#/chat · documents · question-bank · settings）
    ↓ HTTP /api/v1/*
apis/         路由、参数校验、Depends 注入
    ↓
services/     入库 / 检索 / 生成 / 拒答 / LLM 注册（不 import FastAPI）
    ↓
storage/      Chroma 向量 + SQLite 元数据与目录
```

**依赖规则**：

- `apis/` 只做 HTTP，不写 RAG 细节
- `services/` 不 import FastAPI
- `apis/` 不写 try/except（由全局异常处理器统一处理）
- `services/` 不捕获异常（除非转为 AppException）

## 2.2 services 划分

| 模块 | 文件 | 职责 |
|------|------|------|
| 入库 | `ingestion.py` + `ingestion_parts/` | `ingest_file` 编排解析、分块、向量化与写入；文本分块、结构化切片、章节推断在内部模块 |
| 解析 | `parsing.py` + `parsing_adapters/` | `parse_file` 保持统一入口；按格式交给 PDF、Office、Markdown、TXT 适配器 |
| 查询编排 | `query.py` | 按 mode 路由，串联检索与生成 |
| 意图路由 | `intent.py` | 三层漏斗：规则 → 会话状态 → 受约束 LLM 兜底；产出可审计检索计划 |
| 检索 | `retrieval.py` | 向量 + BM25 → RRF；按场景和生效期过滤，再按权威/时效择证；可选 `rerank.py`（BGE）；阈值过滤 |
| 评估 | `eval_metrics.py` | Recall@K / MRR（离线） |
| 生成 | `generation.py` | 拼 prompt、调 LLM、组装 citations |
| Embedding | `embedding.py` | 本地 sentence-transformers 或 OpenAI 兼容 API |
| LLM | `llm.py` | OpenAI 兼容对话 API |
| 模型注册 | `llm_providers.py` | `data/llm_providers.json`；活跃项同步 `.env` |
| Agent 编排 | `agent/` | P2-B LangGraph 多步检索循环；P2-C 通过 `agentic=true` 启用受控 function-calling，P2-B 仍为默认/降级 |
| 存储 | `storage/` | `vector_store` · `doc_store` · `catalog_store` |

**对外入口**（services 层）：

```python
ingestion.ingest_file(path, course_id=...) -> doc_id
query.ask(question, course_id=..., mode="qa") -> Answer
```

## 2.3 入库流程

```
POST /api/v1/documents（Form course_id 必填）
  → apis/v1/documents.py
  → services/ingestion.py
       → parsing.parse_file（pdf / txt / md / doc / docx / pptx）
           → PDF: MinerU 结构解析（失败回退 PyMuPDF/OCR）
       → 结构化语义切片（标题层级 / 表格 / 公式 / 图片）或通用 chunk_size / overlap
       → embedding
       → vector_store.upsert + doc_store.update_status
```

解析内部按格式分工：`pdf/strategy.py` 选择解析候选并评估质量，`pdf/mineru_adapter.py`、`pdf/markpdfdown_adapter.py`、`pdf/pymupdf_adapter.py` 处理具体解析器；`office/docx_adapter.py` 读取 Word 内容，旧 `.doc` 经 `office/legacy_doc_converter.py` 转为临时 DOCX 后复用它，`office/pptx_adapter.py` 处理幻灯片；`text/markdown_adapter.py` 保留 Markdown 标题供章节推断，`text/txt_adapter.py` 处理纯文本，两者共享编码回退。PDF 公式与视觉处理位于 `enrichment/`。所有适配器返回 `ParsedDocument`，入库随后按有无结构化 blocks 选择切片路径。

同一物理路径不会跨课改归属；扫描 `data/knowledge/` 亦须带 `course_id`。

## 2.4 查询流程

```
POST /api/v1/ask（JSON course_id 必填）
  → apis/v1/ask.py
  → services/query.py
       → mode（qa | concept | chapter）
       → qa/concept：retrieval.retrieve（filter course_id；向量+BM25→RRF；可选 BGE 精排）
       → chapter：vector_store.get_by_chapter（不走语义检索）
       → 最高分 < score_threshold → grounded: false 拒答
         （精排开启时阈值为 sigmoid(rerank logit)）
       → generation（concept / chapter 专用 prompt）→ answer + citations + grounded
```

`stream: true` 时为 SSE：`phase` → `delta` → `done`。

## 2.6 数据模型

**目录表**（`catalog_store.py`，与 documents 同库）：

```sql
colleges(id, name, created_at)
courses(id, college_id, name, created_at)  -- 检索隔离边界
```

默认种子：`college-default` / 默认学院，`course-default` / 默认课程。

**Chunk 元数据**（写入 Chroma；检索必须 filter `course_id`）：

```python
{
    "doc_id": str,
    "college_id": str,
    "course_id": str,          # 检索必 filter
    "course": str,
    "source_file": str,
    "page": int | None,
    "chunk_index": int,
    "chapter": str | None,
    "doc_type": str | None,
    "block_type": str | None,     # text / title / table / formula / image(_summary)...
    "section_path": str | None,   # 标题层级路径
    "table_headers": str | None,
    "context": str | None,
    "source_version": str,
    "effective_from": "YYYY-MM-DD",
    "effective_to": "YYYY-MM-DD",
    "authority_level": int,      # 数值越大权威越高
    "authority_label": str,
    "applicability_scope": str,  # all 或人工维护的场景键
}
```

**SQLite `documents` 表**：

```sql
id, filename, file_path, status, chunk_count, course, course_id, created_at,
content_hash, logical_name, version_number, previous_doc_id, superseded_by, is_active, updated_at,
source_version, effective_from, effective_to, authority_level, authority_label,
applicability_scope, metadata_confidence, metadata_source
-- status: pending | processing | done | failed | superseded
```

删文档须同时更新 `doc_store` 并 `vector_store.delete_by_doc_id()`。PDF 更新时创建新 `documents` 记录：新版向量先以 `is_active=false` 入库，成功后激活新版并将旧版标记为 `superseded`。多学科隔离见 [04 §4.2](./04-后续演进规范.md)。

## 2.7 API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/health` | 连通性 |
| GET / PATCH | `/api/v1/config` | 读写配置 |
| GET / POST | `/api/v1/llm-providers` | 列出 / 注册模型 |
| POST | `/api/v1/llm-providers/active` | 切换当前模型 |
| DELETE | `/api/v1/llm-providers/{name}` | 删除注册项 |
| POST | `/api/v1/embedding/warmup` | 预热本地 Embedding |
| GET | `/api/v1/colleges` | 学院列表 |
| GET | `/api/v1/courses` | 课程列表；可选 `?college_id=` |
| POST | `/api/v1/documents` | 上传入库；Form **必填** `course_id` |
| GET | `/api/v1/documents` | 资料列表；**必填** `?course_id=` |
| GET | `/api/v1/documents/summary` | 资料分类概览；`?course_id=` 必填，`by=type\|chapter`（默认 `type`） |
| POST | `/api/v1/documents/scan` | 扫描 knowledge；Form **必填** `course_id` |
| PATCH | `/api/v1/documents/{doc_id}/evidence` | 人工覆盖版本、生效期、权威及固定场景；`course_id` 必填 |
| DELETE | `/api/v1/documents/{doc_id}` | 删除；**必填** `?course_id=` 且须匹配归属 |
| POST | `/api/v1/ask` | 问答；JSON **必填** `course_id`；支持 `mode=auto|qa|concept|chapter` / `stream` / `scenario` / `as_of`；响应含 `intent` |
| POST | `/api/v1/agent/run` | Agent 多步问答；JSON **必填** `course_id`；可选 `scenario` / `as_of` / `agentic`；`max_steps` 上限 |

版本前缀由 `API_V1_PREFIX` 控制，默认 `/api/v1`。`course_id` 不存在 → 404；缺省 → 422。

**POST /ask 响应示例**：

```json
{
  "code": 200,
  "data": {
    "answer": "...",
    "citations": [
      {"source_file": "第3章.pdf", "page": 12, "snippet": "...", "score": 0.85}
    ],
    "grounded": true
  }
}
```

响应格式见 [03-工程规范.md](./03-工程规范.md) §3.5。

## 2.8 扩展预留

| 扩展项 | 做法 |
|--------|------|
| 混合检索 / 精排 | 已落地：BM25+RRF；`RERANK_ENABLED` 时 CrossEncoder 精排（`rerank.py`） |
| 新查询模式 | `qa` / `concept` / `chapter` 均已落地 |
| 换 PostgreSQL + pgvector | 替换 `storage/` 实现，services 接口不变 |
| 用户鉴权 | `dependencies.get_current_user()` 占位，MVP 返回 None |
| 多学科隔离 | 已实现：`course_id` + 检索 filter；见 [04](./04-后续演进规范.md) §4.2 |
| Agent 编排 | P2-B 已落地：LangGraph 包在 RAG 外（`services/agent/` + `/agent/run`）；P2-C 以显式 `agentic` 开关接入只读 function-calling，P2-B 保持默认/降级；见 [04](./04-后续演进规范.md) §4.4 |

## 2.9 实施顺序（历史）

P0–P2-C、PDF 结构化解析与 WebUI 已落地；P2-C 保持 P2-B 默认/降级，需通过显式 `agentic=true` 启用。P3 仍按明确平台化需求启动。启动与环境变量见 [03](./03-工程规范.md) §3.10；UI 契约见 [05](./05-WebUI规划.md)。
