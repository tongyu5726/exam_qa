## 1. 结论与目标

主要问题集中在后端：同一份 chunk 被拆开再组装、引用字段多套构造、配置映射逐字段重复、普通与流式问答重复编排，以及已有过滤器未被统一复用。前端已按功能拆分，没有发现同等级的大文件膨胀。

优化目标是减少必须同步修改的位置、中间状态和重复执行的工作。文件变短、类变多或目录变细本身不是验收标准。保留 FastAPI、Vue 3、Chroma、SQLite、现有两条 RAG 流水线及产品能力；不引入通用规则引擎、查询 DSL、MCP/Skills、登录或长期记忆。

## 2. 统计口径

- 后端生产代码：`src/**/*.py`，含空的 `__init__.py`。
- 前端生产代码：`frontend/src/` 中的 `.js`、`.vue`、`.css`，排除 `*.test.js`。
- 后端测试及评估代码：`tests/**/*.py`，包含 fixtures 的生成脚本及 eval 入口，并非全是 pytest 用例。
- 前端测试：`frontend/src/**/*.test.js`。
- 物理行：按文件逐行统计，包含空行、注释和多行字符串。非空行：仅排除空白行，仍包含注释、模板和样式，不是可执行语句数。
- 不计根目录启动脚本、`tools/`、前端构建配置、依赖锁、文档、数据、字体、第三方依赖、缓存和 `www-dist/`。
- 数字只用于定位检查对象，不能据此判定功能价值、测试充分性或可删除比例。

## 3. 已确认的问题与方案

优先级 A：首轮处理，收益明确；B：第二轮处理；C：保留功能并进一步验证。以下代码位置对应本次快照，后续修改可能移动行号。涉及行数是检查范围，绝不等同于可删行数，范围之间可能重叠。

### O1 配置映射与保存耦合（A）

位置：[配置接口](../src/apis/v1/config.py)，`_patch_to_env`，当前约 L150–348，共 199 行。

**证据：**普通字段大量重复 `if field in p → 转换 → updates[ENV_NAME]`。字段还要分别出现在 dataclass、Patch 模型、读取响应及前端 fields 中。更关键的是 L169 的 `sync_active_fields_from_patch` 会保存模型注册表，而后续分块、解析及端口校验尚未全部通过。

**影响：**新增配置需要多处同步；混合修改 LLM 与非法分块参数时，存在接口失败但注册表已经保存的路径。此为源码控制流确认，尚未做故障注入复现。

**方案：**普通字段用明确映射表和少量序列化规则；特殊 URL、密钥掩码、跨字段约束保持专用校验。转换函数只生成待写内容，全部校验通过后再执行注册表和 `.env` 保存。持久化失败的一致性处理应在实施时明确，不宣称两文件天然具备事务。

**验收：**无效请求不改注册表或 `.env`；掩码密钥不覆盖真实密钥；布尔和数值格式正确；环境变量优先级、热更新及重启提示保持现行契约。

### O2 chunk 往返转换与平行数组（A）

位置：[入库](../src/services/ingestion.py)，L195–266，72 行。

**证据：**结构化分块已经是记录列表，却提取为文本、页码、章节、类型、路径、表头、上下文、bbox、页标签、教材引用、内容角色、图片路径、图注共 13 组数组，随后按下标重新组装。非结构化路径另造对应默认数组。

**影响：**中间状态多；数组顺序必须一致；大量下标越界默认值掩盖数据契约问题。

**方案：**两种分块路径直接产出统一记录列表；向量化仅提取文本；逐条补充 doc_id、course_id、索引、解析和证据属性。优先复用现有 chunk 结构，避免新增大规模类型框架。

**验收：**结构化与普通文本的内容、顺序、章节、公式、表格、图片和证据字段保留；embedding 与 chunk 一一对应；入库失败清理、批量写入和版本切换不退化。

### O3 引用字段多套构造并已漂移（A）

位置：[生成](../src/services/generation.py) L77–107、[题库](../src/services/question_bank.py) L31–54、[Agent 工具](../src/services/agent/tools.py) L45–66、[查询出口](../src/services/query.py) L66–95。

**证据：**前三处分别构造引用；查询出口再次逐字段映射。问答包含证据治理及解析来源字段；题库缺少部分解析来源；Agent 工具缺少版本、生效期、权威、范围和择证解释等，响应模型可能用默认值补齐。Agent 的 doc_id 注释也仍称其为被响应模型忽略的内部字段，与当前 Citation 定义不一致。

**影响：**同一条证据从不同入口返回的信息不同；默认值可能被误读为真实元数据。

**方案：**统一命中转引用的构造入口，显式接收 scenario/as_of/evidence_role。保留各业务对证据选择、去重和展示字段的真实差异；引用校验模型负责输出契约，取消重复的机械映射。

**验收：**同一命中的基础属性一致；模型选源与检索候选角色不混淆；缺失值不制造确定性；题库、普通问答、流式问答、Agent 均覆盖。历史引用兼容读取。

### O4 普通与流式问答重复编排（A）

位置：[查询](../src/services/query.py)，`ask` L212–268 和 `ask_stream` L271–349，共 136 行。

**证据：**两条入口分别完成校验、历史读取、意图识别、出题路由、检索、拒答、视觉复核、模型检查、保存和引用转换。

**方案：**共享查询准备和结果收尾；保留普通生成及 SSE 的输出方式。共享准备不能导致流式 phase 延后到耗时检索之后；不强行把普通入口改成消费 SSE，也不新增通用工作流框架。

**验收：**相同输入的范围、模式、拒答、引用和落库一致；保持 SSE phase/delta/done/error、视觉阶段提示和出题跳转；失败不重复保存。

### O5 Chroma 过滤规则重复（B）

位置：[向量库](../src/services/storage/vector_store.py)，`_evidence_where` L324–347、`get_chunks` L367–392、`get_by_chapter` L597–612；[BM25 内存筛选](../src/services/retrieval.py) L231–240。

**证据：**search 已调用公共过滤器，get_chunks 仍独立构造课程、活跃版本、场景和日期规则；章节读取再以内存方式重复范围筛选。

**方案：**让 Chroma 读取入口复用现有过滤构造器，再追加文档、页码等专属条件。Python 内存筛选与数据库表达式确有差异，可共享业务语义和一致性用例，不能机械合并成一种表达式。

**验收：**所有入口强制课程隔离，活跃版本、all 场景、固定场景、有效期边界一致；章节精确/模糊匹配规则不变。

### O6 Agent 与主链路图表能力重叠（B）

位置：[工具](../src/services/agent/tools.py) `analyze_chart` L198–278；[视觉检索](../src/services/retrieval.py) L143–206；[视觉复核](../src/services/query.py) L161–209；[终止节点](../src/services/agent/nodes.py) L115–116。

**证据：**工具重复图片检索、排序和去重，再导入 query 的私有复核函数；主链路视觉检索还提供查询缓存、图号匹配等，行为已有差异。finish_node 只返回空字典。quote_source 与 search_pdf 都重新检索并返回 citations。

**方案：**统一公共视觉能力，普通查询和 Agent 仅编排；保留工具特有的 doc_id/page 读取模式。图的终止边直接结束，消除空节点。quote_source 首先共享实现；是否移除公开工具名称取决于兼容性证据，不能仅凭前端没调用而删除。

**验收：**图号命中、去重、课程/场景/日期范围一致；保留白名单、循环上限、脱敏观测、P2-B 默认及 P2-C 降级。禁止扩大模型权限。

### O7 相同 OCR 候选重复执行（B）

位置：[PDF 策略](../src/services/parsing_adapters/pdf/strategy.py)，L95–100 与 L108–115。

**证据：**普通解析和首次强制 OCR 成功但质量不足、fitz 也不足时，最终回退再次以相同参数执行强制 OCR 和公式增强。

**方案：**保存已尝试候选及其质量，复用同参数的成功结果；首次失败是否重试应明确分类，不能为了去重取消有理由的失败恢复。

**验收：**上述低质量路径同参数成功 OCR 至多执行一次；最佳候选选择、OCR 开关、异常回退保持；使用替身统计调用次数，无需真实模型下载。

### O8 列表/公式证据扩展重复整理（C）

位置：[检索](../src/services/retrieval.py)，列表补全 L339–455（117 行），公式邻页扩展 L458–534（77 行），另有编号解析及最终合并。

**证据：**两种扩展重复按文档分组、读取、复制 metadata、去重及继承锚点分数。列表路径反复解析同一文本编号，先读取最多 2,000 块再筛邻近窗口；公式路径最多读取 500 块再筛同页/邻页。

**方案：**先在一次调用内缓存编号解析并减少重复遍历；如评估确认读取成本明显，再增加受限的邻近读取能力。列表与公式的选择规则保留差异，不为复用创建泛化策略框架。

**验收：**完整枚举、重叠去重、公式邻页召回及 prompt 数量限制保持；同一批固定用例比较答案、引用和拒答，记录读取量及耗时。没有消融评估前不删召回能力。

## 4. 不列入首轮删除的复杂度

- MinerU：表格、图注、页码、Markdown/JSON 输出兼容、原图资源持久化都有实际来源。拆文件只改善定位，不能作为减复杂度成果。
- 版本更新：新版成功后再替换旧版、历史元数据保留是强制产品能力。
- 证据治理：课程、场景、时效及权威选择不可为了少写代码而弱化。
- Embedding：本地/远程双实现和设备选择是实际变化点；下载进度 monkey patch 可后续独立评估，保留配置热更新和旧线程保护。
- 练习：快照、幂等、提交前隐藏答案、客观判分/主观自评、历史保留均对应当前功能。
- 前端：优先处理明确的请求竞态和重复状态，暂不继续机械拆分小组件或更换 UI 库。

        $lines = @(Get-Content -LiteralPath $file.FullName)
        [PSCustomObject]@{
            Area = $area
            Lines = $lines.Count
            Nonblank = @($lines | Where-Object { $_.Trim() }).Count
        }
    }
}
$rows | Group-Object Area | ForEach-Object {
    [PSCustomObject]@{
        Area = $_.Name
        Files = $_.Count
        Lines = ($_.Group | Measure-Object Lines -Sum).Sum
        Nonblank = ($_.Group | Measure-Object Nonblank -Sum).Sum
    }
} | Format-Table
